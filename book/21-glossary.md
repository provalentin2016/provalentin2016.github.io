# Приложение A. Глоссарий

Термины расположены по алфавиту. В скобках — главы, где термин разобран.

**ACP (Agent Client Protocol)** — протокол между агентом и редактором: сессии, поток сообщений, вызовы инструментов, подтверждения. Junie реализует его и добавляет собственные расширения (гл. 17).

**Agent token** — credential, по которому сервер узнаёт конкретного агента. Хранится в виде хеша (гл. 19).

**Алиас модели** — стабильное короткое имя (`gpt`, `opus`), которое ведёт на конкретную модель. Позволяет менять модель, не меняя конфигурацию пользователя (гл. 16).

**Артефакт** — промежуточный результат работы агента с явным типом и идентификатором. Основа конвейера генерации (гл. 1).

**Белый список зависимостей** — список пакетов, которые агенту разрешено установить (гл. 4).

**Бюджет токенов** — ограничение объёма истории, которое агент поддерживает, оценивая токены по символам и калибруя оценку по ответам провайдера (гл. 14).

**Воркер** — небольшой этап конвейера с собственным промптом, форматом ответа и артефактом (гл. 1).

**Eco mode (режим экономии)** — планирование выбранной моделью и реализация более дешёвой моделью (гл. 16).

**Effort (уровень усилия)** — степень рассуждения модели перед ответом. Набор уровней зависит от модели (гл. 16).

**EmbArk** — индексация и поиск по коду с парсерами для нескольких языков (гл. 14).

**Evals** — оценка качества агента на наборе задач. Дорогой уровень проверки (гл. 10).

**ExecutionContext (контекст выполнения)** — узел дерева вызовов агента: родитель, запрос, статистика (гл. 7).

**FileChange** — объект изменения файла с содержимым «до» и «после». Основа диффа и отката (гл. 8).

**Goal (цель)** — долгоживущее состояние сессии, которое агент держит между промптами (гл. 18).

**HITL (human in the loop)** — подтверждение действий пользователем с режимами `AllowAll`, `AskAll` и `Interactive` (гл. 8).

**HistoryProcessor (обработчик истории)** — стратегия сокращения истории шагов агента (гл. 2, гл. 14).

**JUNIE_HOME** — каталог пользовательских данных Junie: логи, настройки, сессии, кэш (гл. 11, гл. 12).

**Junie Live** — сервис, в котором агент работает как долгоживущий процесс с журналом событий и командами (гл. 19).

**Junie Mix** — готовый профиль с уровнями `lite`, `normal`, `hard`, `frontier` (гл. 16).

**Kineto** — линия генератора, удалённая из HEAD в ноябре 2025 года (гл. 4, гл. 5).

**MCP (Model Context Protocol)** — протокол, по которому внешние серверы сообщают агенту свои инструменты (гл. 13).

**Нативный лаунчер** — программа на Rust, которая запускает JVM в собственном процессе с сохранением имени и поведения сигналов (гл. 12).

**Песочница (sandbox)** — ограничение команд агента через `srt`: какие каталоги писать и читать (гл. 15).

**Правило возможностей** — расширения ACP включаются по объявленной возможности клиента, а не по его идентичности (гл. 17).

**RootExecutionContext (корень выполнения)** — владелец ресурсов задачи. Закрывает их один раз, в порядке регистрации (гл. 7).

**RPC-схема** — описание сервиса на собственном DSL, из которого генерируются клиент и сервер IDE (гл. 13).

**Рецепт (recipe)** — проверенная инструкция с описанием, зависимостями и фрагментами кода. Выбирается моделью из индекса, проверяется кодом (гл. 4).

**Снимок состояния (snapshot)** — архив состояния рантайма агента, хранимый вне сервера (гл. 19).

**Steering** — сообщение пользователя во время работы агента. Исход — `injected` или `startedNewTurn`, но не ошибка (гл. 18).

**Subagent (субагент)** — вложенный цикл агента с собственной беседой, который возвращает один результат (гл. 9).

**SWE-agent** — подход, который Matterhorn воспроизводил в 2024 году для цикла действий (гл. 2).

**Steerable command** — команда, которую можно выполнить во время работы агента (гл. 18).

**TeamCity-логгер** — вывод сервисных сообщений TeamCity с идентификатором потока для параллельных запусков (гл. 3).

**Фильтр возможностей** — выбор подмножества MCP-серверов для задачи. Отфильтрованный сервер можно включить инструментом `enable_mcp` (гл. 13).

**Worktree** — отдельная git-копия рабочего каталога, в которой субагент работает изолированно (гл. 9).
